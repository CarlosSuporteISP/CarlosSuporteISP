# 🚀 Installation and profile optimisation guide

This package is prepared for the special GitHub profile repository:

```text
CarlosSuporteISP/CarlosSuporteISP
```

GitHub displays the root `README.md` of a public repository whose name exactly matches the account username.

## 1. Create or prepare the profile repository

1. Create a **public** repository named `CarlosSuporteISP`.
2. Do not add a template README if the repository is new.
3. Extract this package into the root of the repository.
4. Push all files.

Example:

```bash
git clone https://github.com/CarlosSuporteISP/CarlosSuporteISP.git
cd CarlosSuporteISP

# Copy the extracted files into this directory.

git add .
git commit -m "feat: create professional GitHub profile"
git push
```

## 2. Enable GitHub Actions write access

Open:

```text
Repository → Settings → Actions → General → Workflow permissions
```

Select:

```text
Read and write permissions
```

Save the setting.

The workflows only write generated SVG files into the profile repository.

## 3. Run the three workflows once

Open the **Actions** tab and manually run:

1. `Update profile cards`
2. `Generate contribution snake`
3. `Generate 3D contribution calendar`

After the first successful run, the following files will exist:

```text
profile/stats-dark.svg
profile/stats-light.svg
profile/top-langs-dark.svg
profile/top-langs-light.svg
profile/snake.svg
profile/snake-dark.svg
profile-3d-contrib/profile-night-rainbow.svg
```

The workflows then update automatically once per day.

## 8. Community features

For repositories intended for collaboration:

- Enable **Discussions**.
- Add `good first issue` and `help wanted` labels.
- Create a roadmap in GitHub Projects.
- Use issue forms for bugs and feature requests.
- Add contribution examples.
- Reply to issues with technical context and closure notes.
- Link upstream issues and pull requests when the project is a fork.

## 9. Private contribution visibility

To show private activity without exposing repository names:

```text
GitHub profile → Contribution settings → Include private contributions
```

The default workflow token is sufficient for public statistics. A personal access token is only necessary when a generator must query additional private data. Never commit tokens to the repository.

## 10. External visual components

The typing animation uses `readme-typing-svg` and the clickable badges use `shields.io`.

The statistics, language cards, contribution snake and 3D calendar are generated by GitHub Actions and saved in your own repository. This avoids depending on a public statistics endpoint every time someone opens the profile.

## 11. Recruiter-focused maintenance

Review the profile every three months:

- Update current role and availability.
- Replace weak or inactive pinned repositories.
- Add outcomes and measurable results to project READMEs.
- Archive abandoned experiments.
- Keep screenshots current.
- Publish releases instead of leaving only raw commits.
- Add English documentation first for international reach.
- Keep the most important information visible before collapsible menus.
